# Contributing

## Add one control at a time

Every pull request should normally implement or improve one control.

## Required PR content

- control ID;
- problem and threat scenario;
- completed one-page README summary with target, action, success state, and
  residual boundary;
- files changed;
- insecure and secure behavior;
- verification evidence;
- dependencies or permissions added;
- framework mappings;
- limitations;
- rollback approach.

## Dependency additions

For every new package, Action, binary, Skill, MCP server, or plugin, document:

- purpose;
- canonical source;
- exact immutable version;
- integrity verification;
- permissions;
- network access;
- maintenance status;
- alternatives;
- removal plan.
